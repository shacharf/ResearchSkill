---
name: rs-research
description: Collaborate on a single research thread, preserving evidence and checkpoints in an rsagent project.---

Run `rsagent status --json` once at startup. Read only its bounded project brief and active resume; if either is marked excerpted, retrieve the named section deliberately. If no thread is active, offer a compact `rsagent threads` selection or create one at the user's direction. Keep one immediate question in focus. Park tangents with `rsagent todo "topic and motivation"`, then continue the question.
Markdown is authoritative. Source notes describe individual sources; thread records hold our interpretations, experiments, accepted/rejected/deferred ideas with reasons, uncertainties and evidence locations. Distinguish tentative proposals from user-confirmed conclusions. Use direct deterministic rsagent commands for bookkeeping, with quoted shell arguments. Never run Git commands. Never edit paper.md unless explicitly asked to write manuscript material.
Checkpoint after meaningful conclusions, useful evidence, direction changes, and before switching or ending a session. Use rs-save's workflow; routine recordkeeping needs no approval. Do not checkpoint every message. Saved records must preserve reasoning, examples, qualifications and rejected alternatives, not just conclusions. Abrupt exits can lose unsaved conversation.
Known IDs, resumes and lists use direct commands. Discover unknown past arguments with `rsagent search "phrase"` for lexical lookup, or `rsagent search "concept" --hybrid` for concepts. Keep results bounded; read exact evidence passages and report locations and thread status. Obsolete threads remain discoverable but are not current conclusions. Do not use GNO answer generation, unrelated default collections, or Git-enabled options. A search miss is not proof of absence. Manual edits require `rsagent checkpoint` to schedule synchronization. Search freshness may lag saved Markdown; inspect `rsagent index status` and retry with `rsagent index flush` if needed.

Papers: refer to registered papers only by number. Before the first discussion of an `x`-prefixed paper run `rsagent paper discuss REF`; it assigns the next discussion number (never changed afterwards) and updates references. When switching to a paper that has no saved overview, first follow rs-paper: read the full PDF and present the initial overview (rs-paper/overview.md), saving it with `rsagent paper overview REF`. Summaries follow the rs-paper format, use the discussion's clarifications to improve on that overview, and are written at checkpoints, not only when a thread closes.
